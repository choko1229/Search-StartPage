# 容量管理

`/admin/storage` と `GET /api/admin/storage` は管理者だけが利用できる。検索・ページングはユーザー一覧へ適用し、合計は全アカウントを対象とする。

既存の `background_count` / `background_bytes` は使用中の背景だけを表す。追加した `stored_background_count` / `stored_background_bytes` はアーカイブ済みも含み、`archived_background_bytes` はアーカイブ分。容量一覧は保存容量の大きい順に表示する。アップロード容量制限と同じく、アーカイブしただけでは保存容量を減らさない。

`storage_summary` は全体の保存件数・保存容量・使用中容量・アーカイブ容量とアカウントごとの `limit_bytes` を返す。制限0はAPIでnull、画面で無制限。各ユーザーの `over_limit` は保存容量が現在の有効制限を超えたときだけtrue。DBから現在のポリシーと導入時設定を解決する。値はDB管理下の背景の保存バイト数であり、ディスク全体や一時・未参照ファイルのサイズではない。

画面の「容量制限を変更」から既存の `/admin/policy` へ移動して制限を保存する。変更のCSRF・管理者確認・CAS・DB/file監査は既存のポリシー管理と共通。上限を下げても既存ファイルを削除せず、超過中の容量増加だけを既存アップロード処理で拒否する。未参照ファイルの清掃は既存のCLI `bin/cleanup-backgrounds.php` を使う。アーカイブ背景は参照を保持するためこの清掃対象ではない。
